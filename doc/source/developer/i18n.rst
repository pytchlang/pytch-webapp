Translations / Internationalisation
===================================

Different languages are supported by means of the ``i18next`` library
and its ``react-i18next`` wrapping.  All user-facing strings should be
generated by calls to a translation function, usually obtained with
code like

.. code-block:: typescript

   const { t } = useTranslation("ide");

inside a React component function.

Apart from the help-sidebar content (see below), the strings are
divided into *namespaces*, with the app reading data for each
namespace from its own JSON file
``public/locales/LANG-CODE/NAMESPACE.json``.  In the above code
example, the namespace is ``ide``.

For incomplete translations, ``en`` is used as a fallback language.


Help sidebar
------------

The help sidebar content exists per language, in

.. code-block:: text

   public/data/help-sidebar/LANG-CODE.json


Source of truth for strings
---------------------------

The source of truth for the strings (including help-sidebar content)
is a *monolithic* JSON file, i.e., one big file containing all strings
for a particular language.  For i18next namespace strings, the
namespace is prepended, so for example the entry

.. code-block:: json

   "actor-action.go-to-code": "Go to code"

in the ``ide`` namespace file for the language ``en`` appears as

.. code-block:: json

   "ide.actor-action.go-to-code": "Go to code"

in the monolithic ``en`` JSON file ``src/data/i18n/en.json``.

The help-sidebar content exists as strings under keys beginning with
the prefix ``help-sidebar``.


Updating app-consumed files from monolithic
-------------------------------------------

The script

.. code-block:: text

   tools/i18n/demux_poeditor_file.py

takes a single argument, being the two-letter language code.  The
script reads the monolithic file and writes the individual files
(collection of i18next namespace files, plus the help-sidebar content)
for that language as read by the app.

An example run might be:

.. code-block:: console

   $ python tools/i18n/demux_poeditor_file.py ga
   INFO: read "src/data/i18n/ga.json"
   INFO: wrote "public/locales/ga/common.json"
   INFO: wrote "public/locales/ga/assets.json"
   INFO: wrote "public/locales/ga/errors.json"
   INFO: wrote "public/locales/ga/flows.json"
   INFO: wrote "public/locales/ga/ide.json"
   INFO: wrote "public/locales/ga/notable-changes.json"
   INFO: wrote "public/locales/ga/projects.json"
   INFO: wrote "public/locales/ga/tutorials.json"
   INFO: wrote "public/locales/ga/vm.json"
   INFO: wrote "public/locales/ga/welcome.json"
   INFO: read "src/data/i18n/en.json"
   INFO: read "src/data/help-sidebar/structure.json"
   INFO: wrote "public/data/help-sidebar/ga.json"

The process reads the monolithic source files for both the target
language (``ga``) and the fallback language (``en``).


Help sidebar app-file generation
--------------------------------

The structure of the help sidebar is language-agnostic and stored in
the file

.. code-block:: text

   src/data/help-sidebar/structure.json

Where required, an entry has a ``slug`` property, which is used as the
stem of a collection of keys in the monolithic strings file.  See code
of the "demux" script for details.


Updating monolithic file
------------------------

The per-language large files are edited using ``POEditor``.  When
there is an update, the maintainer exports the relevant language file,
then runs the above "demux" script, committing the combined changes
(monolithic file and any output files).
